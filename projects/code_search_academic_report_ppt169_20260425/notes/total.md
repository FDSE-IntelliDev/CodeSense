# 01_封面
本次汇报介绍一个面向 Agent Query 的代码搜索框架，目标是在真实工程中同时实现高召回与高精度。我们的方法从 query 结构化开始，经过多路检索、过滤与双阶段重排，最终输出可解释的高质量结果。今天重点放在整体方法链路和关键设计动机。
要点：① 任务目标与场景 ② 方法主链路 ③ 汇报结构
时长：1分钟

---

# 02_背景与挑战
[过渡] 在介绍方法之前，我们先看为什么传统代码检索难以直接服务 Agent Query。
首先，Agent Query 常包含隐式约束，不只是关键词匹配问题。其次，若缺少结构化过滤，候选噪声会显著增加。最后，仅做单元素相关性打分会忽略调用链关系，导致关键函数被低估。[停顿]
要点：① 语义复杂性 ② 噪声问题 ③ 关系信息缺失
时长：1.5分钟

---

# 03_方法总览
[过渡] 针对这些挑战，我们采用一个分阶段、可解释的流水线。
流程从 query 输入开始，经 DSL 解析得到 structured query，然后通过三路检索形成高召回候选集。之后通过规则与语义过滤提升候选质量，最后进行 single 与 group rerank，输出最终结果。
要点：① 五阶段流程 ② 高召回到高质量的收敛 ③ 可解释闭环
时长：1.5分钟

---

# 04_DSL解析
[过渡] 首先看第一步：DSL-Driven query parsing。
我们把自然语言 query 解析为结构化字段，包括关键词、目标类型和过滤约束。这个统一表示使后续模块之间有一致接口，避免“检索、过滤、重排”各自理解 query 的偏差。
要点：① structured query 字段 ② DSL 的接口作用 ③ 对下游模块的支撑
时长：1.5分钟

---

# 05_高召回检索
[过渡] 有了 structured query 后，进入多路高召回检索阶段。
我们组合 grep 正则、倒排索引和 embedding 语义检索三条路径。它们在速度、覆盖与语义泛化能力上互补，联合后能显著降低漏检风险，为后续精筛提供更完整候选池。
要点：① 三路检索互补 ② 高召回目标 ③ 为精筛提供输入
时长：1.5分钟

---

# 06_候选过滤
[过渡] 下一步是把高召回候选收敛为高质量候选。
规则过滤直接利用 DSL 约束，例如 target=function 时去除 class。语义过滤则借助大模型判断候选是否真正符合 filter 的语义要求，过滤掉仅表面相关的结果。[停顿]
要点：① Rule filtering ② Semantic filtering ③ 质量收敛
时长：1.5分钟

---

# 07_single_rerank
[过渡] 过滤后我们进入第一层重排：single rerank。
每个候选元素独立打分，主要包含 LLM 相关性判断、token overlap 和代码权重 scoring。这里既考虑语义匹配，也考虑代码结构特征与 query 偏好，实现更稳健的个体排序。
要点：① 三类单元素信号 ② 语义+结构结合 ③ Top-K 初筛
时长：1.5分钟

---

# 08_group_rerank
[过渡] 仅靠单元素分数仍不够，因此我们引入 group rerank。
关键思想是把调用链或结构关系作为组上下文来重新评估相关性。比如 malloc_disk 单看与 readahead 弱相关，但在 init_readahead 的调用链中，其任务相关性应被提升。
要点：① 组级关系建模 ② 调用链增强 ③ 弱相关节点重估
时长：1.5分钟

---

# 09_融合打分
[过渡] 将 single 与 group 两层信息融合后，得到最终排序分数。
我们使用可调权重融合多类信号，并可依据 query 类型动态调整。这样既保留单点语义匹配能力，也能吸收关系结构带来的全局信息。
要点：① 融合公式 ② 动态权重 ③ 全局相关性提升
时长：1.2分钟

---

# 10_case_study
[过渡] 接下来通过一个 disk + readahead 的实际查询看全链路效果。
从 1200+ 高召回候选经过过滤与重排收敛到可解释的 Top-K 结果。案例中 malloc_disk 的上升体现了 group rerank 的价值，即结构关系能纠正单点评分偏差。
要点：① 候选收敛轨迹 ② Top 结果解释 ③ group 增益示例
