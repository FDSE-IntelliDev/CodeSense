# experiments/

每个实验一个目录，**配置和记录都在里面**，结果归档到 `runs/`（不进版本库）。

```
experiments/
└── EXP-0001-<短横线描述>/
    ├── config.yaml      跑什么（configs/default.yaml 复制一份改）
    └── README.md        为什么跑、结果如何、结论是什么
```

## 命名

`EXP-<四位序号>-<短横线描述>`，序号只增不减。

改过的实验**开新号**，不要原地改旧实验——否则 README 里的结论和配置对不上，
这是实验记录最常见的失效方式。

## 配置要复制不要引用

`config.yaml` 必须是一份**独立的快照**，不要写「用 configs/default.yaml」。
那个文件下周就会被改，到时候你没法知道当时到底跑的什么参数。

## 记录写在跑之前

README 里的「问题」和「假设」是**开跑前**写的，不是跑完补的。
跑完再补，写出来的一定是对结果的事后解释。

建议的结构：

```markdown
# EXP-0001-<描述>

## 问题
这次想验证什么？

## 假设
预期会看到什么？为什么？

## 配置差异
和哪个实验对比，只差哪一个变量？

## 结果
（跑完填）

## 结论
（跑完填）假设成立了吗？下一步做什么？
```

## 消融只改一个变量

对照组和实验组之间**只能差一个变量**。同时改两处，结果变了你也不知道是谁的功劳。

## 跑之前确认工作区是干净的

归档里的 `git_dirty` 必须是 `no`。带着未提交改动跑出来的结果，
三个月后没有任何办法复现——你不知道当时那些改动是什么。
