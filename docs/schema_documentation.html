💡 设计动机

在 CodeSearch 引擎中，我们需要处理来自多种编程语言的代码元素。不同语言的解析器产生不同格式的数据结构， 这导致了数据异构、特征抖动和序列化不稳定等问题。统一的 Schema 设计旨在解决这些挑战。

🎯 统一表示

为 Java、Python、C++、JavaScript、Go、Rust 等语言提供一致的代码元素表示格式。

📊 特征稳定

确保相同语义的代码元素在不同解析中产生一致的特征向量，减少特征抖动。

🔄 可扩展性

支持语言特定扩展字段，同时保持核心结构的稳定性。

🔧 解决的问题

数据异构问题

不同语言解析器输出的数据结构差异大，难以统一处理。例如：

  • Java：使用 class、method、field
  • Python：使用 function、class、decorator
  • C++：使用 function、struct、template
  • Rust：使用 fn、struct、trait

Schema 通过类型映射表将各种语言类型归一化为标准类型。

特征抖动问题

相同语义的代码因格式差异产生不同的特征表示，影响聚类和检索效果。Schema 定义了明确的字段优先级和提取规则。

序列化不稳定问题

JSON 字段顺序不一致导致哈希值变化，影响索引稳定性。Schema 规定了固定的字段顺序和序列化规范。

system_meta - 系统级元信息

记录代码元素的系统级标识和位置信息，用于索引和追踪。

symbol_id required int | string
代码元素的唯一标识符，用于索引和关联。
filepath required string
源文件的绝对路径或相对路径。
language required enum
编程语言类型：java, python, c, cpp, javascript, typescript, go, rust, other
line_range optional object
代码在文件中的行号范围，包含 start_line, end_line, start_column, end_column。
repository optional string
所属仓库或项目名称。
commit_hash optional string
Git commit 哈希值，用于版本追踪。
{
  "system_meta": {
    "symbol_id": 123,
    "filepath": "/src/main/java/com/example/AuthService.java",
    "language": "java",
    "line_range": {
      "start_line": 45,
      "end_line": 68,
      "start_column": 1,
      "end_column": 2
    },
    "repository": "example-project",
    "commit_hash": "a1b2c3d4"
  }
}

structural_identity - 结构标识

定义代码元素的结构身份，是 Schema 的核心部分。

name required string
符号名称（函数名、类名、变量名等）。
symbol_type required enum
归一化的符号类型：function, method, class, interface, struct, enum, variable, constant, field, property, module, namespace, type_alias, macro, other
container optional object
容器层级信息，包含 container_name, container_type, full_qualified_name。
signature optional string
函数/方法签名，包含参数和返回类型。
parameters optional array
函数/方法参数列表，每个参数包含 name, type, default_value, is_optional, is_variadic。
modifiers optional array
访问修饰符和关键字（public, private, static, async 等）。
parent_types optional array
父类或实现的接口列表。
{
  "structural_identity": {
    "name": "sendSmsLoginCode",
    "symbol_type": "method",
    "container": {
      "container_name": "AuthServiceImpl",
      "container_type": "class",
      "full_qualified_name": "com.example.AuthServiceImpl.sendSmsLoginCode"
    },
    "signature": "sendSmsLoginCode(String mobile, String code)",
    "return_type": "void",
    "parameters": [
      {"name": "mobile", "type": "String"},
      {"name": "code", "type": "String"}
    ],
    "modifiers": ["public", "async"],
    "parent_types": ["AuthService"]
  }
}

semantic_context - 语义上下文

包含代码元素的语义信息，用于功能检索和语义匹配。

docstring optional string
文档字符串或注释内容。
code_snippet optional string
实际源代码内容。
summary optional string
AI 生成的代码功能摘要。
annotations optional array
注解/装饰器列表（如 @Override, @Transactional, @pytest.fixture）。
keywords optional array
从代码中提取的关键词。
domain_terms optional array
代码中识别的领域特定术语。
{
  "semantic_context": {
    "docstring": "Sends an SMS verification code for user login authentication",
    "code_snippet": "public void sendSmsLoginCode(String mobile, String code) {\n    SmsMessage message = new SmsMessage(mobile, code);\n    smsClient.send(message);\n}",
    "annotations": ["@Override", "@Async", "@Transactional"],
    "keywords": ["sms", "login", "verification", "authentication"],
    "domain_terms": ["user authentication", "SMS verification"]
  }
}

relations - 关系信息

记录代码元素与其他元素之间的关系，用于依赖分析和调用图构建。

calls optional array
此元素调用的函数/方法列表。
called_by optional array
调用此元素的函数/方法列表。
references optional array
此元素引用的变量或类型。
referenced_by optional array
引用此元素的元素列表。
depends_on optional array
此元素依赖的文件或模块。
tests optional array
测试此元素的测试函数列表。
{
  "relations": {
    "calls": ["SmsClient.send", "SmsMessage."],
    "called_by": ["LoginController.login"],
    "depends_on": ["com.example.sms.SmsClient", "com.example.model.SmsMessage"]
  }
}

inferred_tags - 推断标签

AI 推断的语义标签，用于增强检索和分类。

{
  "inferred_tags": ["login", "sms", "authentication", "verification"]
}

标签来源包括：

  • 名称推断：从函数名、类名提取的关键词
  • 语义推断：基于 docstring 和代码内容的语义分析
  • 领域推断：识别的领域特定概念

language_extensions - 语言扩展

存储语言特定的扩展字段，保持核心 Schema 简洁的同时支持语言特性。

{
  "language_extensions": {
    "java": {
      "throws": ["SmsException"],
      "is_synchronized": false
    }
  }
}
{
  "language_extensions": {
    "python": {
      "is_coroutine": true,
      "decorators": ["retry"]
    }
  }
}
{
  "language_extensions": {
    "cpp": {
      "template_params": [],
      "is_constexpr": false,
      "is_noexcept": false
    }
  }
}

def normalize_symbol_type(language: str, raw_type: str) -> str:
    """Normalize symbol type to standard enum value"""
    lang_map = LANGUAGE_TYPE_MAP.get(language.lower(), {})
    normalized = lang_map.get(raw_type.lower())
    if normalized:
        return normalized.value
    return SymbolType.OTHER.value

生成特征文本

Schema 支持多种特征提取模式，用于不同场景的嵌入生成：

模式 包含字段 适用场景
full structural_identity, semantic_context, relations, inferred_tags 综合嵌入，用于语义检索
structural structural_identity 签名匹配，用于精确查找
semantic semantic_context, inferred_tags 功能检索，用于语义搜索
minimal name, signature 快速索引，用于轻量匹配 
from parsers.schema_converter import schema_to_feature_text

# Full 模式 - 包含所有信息
feature_full = schema_to_feature_text(schema, mode="full")
# name: sendSmsLoginCode | type: method | signature: sendSmsLoginCode(String mobile, String code) | container: AuthServiceImpl | doc: Sends an SMS verification code... | calls: SmsClient.send

# Structural 模式 - 仅结构信息
feature_structural = schema_to_feature_text(schema, mode="structural")
# name: sendSmsLoginCode | type: method | signature: sendSmsLoginCode(String mobile, String code) | container: AuthServiceImpl

# Semantic 模式 - 仅语义信息
feature_semantic = schema_to_feature_text(schema, mode="semantic")
# doc: Sends an SMS verification code for user login authentication | code: public void sendSmsLoginCode...

# Minimal 模式 - 最小表示
feature_minimal = schema_to_feature_text(schema, mode="minimal")
# name: sendSmsLoginCode | signature: sendSmsLoginCode(String mobile, String code)

聚类中的 Schema 使用

# clustering/schema_clusterer.py 中的使用示例

class SchemaClusterer:
    def __init__(self, embedding_model, feature_mode="full"):
        self.embedding_model = embedding_model
        self.feature_mode = feature_mode
    
    def prepare_features(self, schemas: List[SymbolSchema]) -> np.ndarray:
        """将 Schema 转换为特征向量"""
        features = []
        for schema in schemas:
            # 生成特征文本
            text = schema_to_feature_text(schema, mode=self.feature_mode)
            # 生成嵌入向量
            embedding = self.embedding_model.encode(text)
            features.append(embedding)
        return np.array(features)
    
    def cluster(self, schemas: List[SymbolSchema], n_clusters: int):
        """执行聚类"""
        features = self.prepare_features(schemas)
        # 使用 KMeans 或其他聚类算法
        from sklearn.cluster import KMeans
        kmeans = KMeans(n_clusters=n_clusters)
        labels = kmeans.fit_predict(features)
        return labels

特征提取模式对比

📊 Full 模式

包含结构、语义、关系、标签全量信息。适合语义相似性聚类，生成最丰富的嵌入表示。

🏗️ Structural 模式

仅包含名称、类型、签名、参数等结构信息。适合按 API 签名聚合相似函数。

💬 Semantic 模式

包含文档、代码、标签等语义信息。适合按功能语义聚合。

⚡ Minimal 模式

仅包含名称和签名。适合快速索引和轻量匹配。

✨ 最佳实践 - 字段填充建议

必填字段

  • schema_version：始终使用当前版本 "1.0.0"
  • system_meta.symbol_id：确保唯一性，可使用文件路径+名称的哈希值
  • system_meta.filepath：使用相对于仓库根目录的路径
  • system_meta.language：准确识别语言类型
  • structural_identity.name：使用原始符号名称，不进行规范化
  • structural_identity.symbol_type：通过类型映射表归一化

推荐填充字段

  • structural_identity.signature：对函数/方法强烈推荐，用于签名匹配
  • structural_identity.container：推荐填充，有助于理解上下文
  • semantic_context.docstring：强烈推荐，对语义检索效果显著
  • system_meta.line_range：推荐填充，用于代码定位

可选字段填充时机

  • semantic_context.code_snippet：当需要深度语义分析时填充
  • relations.*：当有调用图分析结果时填充
  • inferred_tags：当有 AI 标注结果时填充
  • language_extensions：当有语言特定信息需要保留时填充

避免的问题

  • 字段顺序不一致：使用 to_dict() 方法保证固定顺序
  • 空值处理不当：不要包含 null 值字段，使用 to_dict() 自动过滤
  • 类型不规范：symbol_type 必须通过 normalize_symbol_type() 归一化
  • 路径不统一：filepath 统一使用相对路径或绝对路径，不要混用

⚡ 性能优化建议

🚀 批量处理
使用 convert_symbols_batch() 批量转换，减少重复计算。
📝 特征长度限制
docstring 限制 500 字符，code_snippet 限制 1000 字符，relations 限制 10 条。
💾 懒加载
code_snippet 可按需加载，不必要时不填充。
🔢 模式选择
根据场景选择合适的特征提取模式，minimal 最快，full 最慢。
📊 缓存优化
对相同代码元素的 Schema 可缓存在内存中，避免重复解析。
🔗 增量更新
仅对变更文件重新生成 Schema，减少全量处理开销。

完整示例代码流程

# 完整的 Schema 处理流程
from parsers.schema_converter import (
    convert_symbols_batch,
    schema_to_feature_text,
    validate_schema
)
from clustering.schema_clusterer import SchemaClusterer

# 1. 解析代码获取 SymbolItems
symbols = parse_codebase("/path/to/repo")

# 2. 批量转换为 Schema
schemas = convert_symbols_batch(
    symbols=symbols,
    code_fetcher=fetch_code_content,
    call_graph=call_graph,
    dependency_graph=dep_graph
)

# 3. 验证 Schema
valid_schemas = []
for schema in schemas:
    errors = validate_schema(schema)
    if not errors:
        valid_schemas.append(schema)

# 4. 特征提取与聚类
clusterer = SchemaClusterer(embedding_model, feature_mode="full")
labels = clusterer.cluster(valid_schemas, n_clusters=20)

# 5. 结果分析
for cluster_id in range(20):
    cluster_items = [s for s, l in zip(valid_schemas, labels) if l == cluster_id]
    print(f"Cluster {cluster_id}: {len(cluster_items)} items")
