Why df is the whole game

ICF is log(N/df) / log(N). Below 0.34 a term stops discriminating, and an expansion onto it is discarded at query time — which is why the grounding stage refuses to generate one. 4,924 of 7,148 terms clear the bar.

Grounding: query word → project spelling

Three rules, scored by how much they can be trusted. A prefix match is close to certain; a subsequence match is a guess.

subseq4,113

prefix 0.75abbrev 0.75subseq 0.50
Subsequence is the largest and the worst. It produces abandoned → add and ability → alt. Those score 0.50 and mostly die at the ICF floor anyway, but the rule is carrying more noise than signal and deserves tightening.

Compound segmentation — 78 terms on this repository

Ronin returns iostat, nfsd and printk whole, so a query for "io statistics" cannot reach a symbol indexed only as iostat. Viterbi over a unigram lattice fixes that, and it needs no training: the costs come from the words the delimiter already split out, counted. The whole word is always kept beside its pieces.

III · The same query, compiled

codegen route · 8.42 s · 40-line generated script

Hand the model the operator spec and the vocabulary with df, and it writes the script itself. This is the artifact: edit one line, re-run it, see what changed.

# Start with a narrow query focused on pooled buffer allocation and recycling
q = QueryUnit("buffer_allocation", satisfiers=(
    LexicalSatisfier(terms=(
        Term("pooled", weight=0.9), Term("buffer", weight=0.9), Term("allocation", weight=0.8),
        Term("recycling", weight=0.8), Term("recycler", weight=0.7), Term("alloc", weight=0.6),
        Term("memory", weight=0.5), Term("free", weight=0.5), Term("deallocate", weight=0.5),
        Term("chunk", weight=0.5), Term("arena", weight=0.5), Term("reuse", weight=0.5),
        Term("cache", weight=0.5), Term("manage", weight=0.4), Term("size", weight=0.4),
        Term("control", weight=0.4), Term("handle", weight=0.4)
    ), weight=0.5),
))

# Evaluate the query to get initial candidates
frag = eval_unit(q, ctx)

# If the initial results are too few, widen the search with additional terms
if len(frag) < 30:
    # Add broader terms to capture more relevant results
    wide = QueryUnit("buffer_allocation_wide", satisfiers=(
        LexicalSatisfier(terms=(
            Term("pool", weight=0.6), Term("recycle", weight=0.6), Term("allocator", weight=0.5),
            Term("buffered", weight=0.5), Term("management", weight=0.5), Term("usage", weight=0.5),
            Term("performance", weight=0.4), Term("strategy", weight=0.4), Term("implementation", weight=0.4),
            Term("configuration", weight=0.4), Term("system", weight=0.4)
        ), weight=0.4),
    ))
    frag = frag | eval_unit(wide, ctx)

# Use graph proximity to find related symbols that may enhance the results
near = reach(top(frag, 20), ctx, edge=["calls", "contains"], direction="any", hops=(1, 2))

# Boost the scores of the original candidates with nearby relevant nodes
boosted = set(near.nodes) & set(frag.nodes)
frag = frag.induced(sorted(
    frag.nodes,
    key=lambda s: (-score_of(frag, s) * (1 + 0.6 * (s in boosted)), s),
)[:60])

# Final intent evaluation to determine the best candidates based on the specific criterion
answer = intent(frag, "Elements that effectively manage pooled buffer allocation and recycling in the Netty codebase.", ctx, max_items=60)
