## 挡住实现的

### Q1. `hop` 的路径爆炸怎么控

三跳、几百个起点，路径数轻松上百万。已知手段：`max_paths` 截断、
双向 BFS、按路径长度剪枝。但**截断意味着结果不完整且不确定**——
同样的查询跑两次可能返回不同的路径子集。

选项：

- **A** 截断但保证确定性（按 symbol_id 排序后取前 N）。可复现，但截掉的
  可能恰好是好结果。
- **B** 不返回全部路径，只返回**端点对 + 一条代表路径**。内存可控，
  但丢掉了「有几条路径连着」这个强信号。
- **C** 惰性求值，`endpoints` 只要端点时不物化路径。实现复杂。

倾向 A + B 组合：默认只留代表路径，需要全部时显式打开。**需要定。**

### Q2. 单元之间的默认关系是 AND 吗

`io performance on disk` 里三个单元，脚本写的是
`io & disk` 然后 `hop(..., perf)`。但这个编排是我手写的，
编译器凭什么这么排？

- 三个单元两两之间可能是：同元素共现（`&`）、图上可达（`hop`）、
  或者根本无关（只是描述同一件事的不同侧面）。
- 组合数随单元数爆炸：3 个单元就有多种排法。

需要一套**编排规则**或者让 LLM 决定并给出理由。倾向后者，
但要有兜底的默认策略。**没想清楚。**

### Q3. 生成脚本的安全边界

[06](06-script-and-execution.md) 列了三条（受限命名空间、AST 白名单、人工确认），
但没定死。核心问题：**白名单允许到什么程度？**

- 只允许算子调用 + 集合运算 + 赋值 → 最安全，但可能表达不了某些查询
- 允许 `if` / `for` → 表达力强，但白名单校验形同虚设

倾向从最窄开始，遇到表达不了的再放宽——**而且每次放宽都应该先问
「是不是缺算子」**。需要真实查询样本来验证窄白名单够不够用。

## 影响设计但不挡实现的

### Q4. `derived` 词的权重怎么定

[04](04-query-unit.md) 给 `buffer` 打了 0.5，但那是拍脑袋。合理的做法：

- 让 LLM 给（一致性差）
- 按项目语料的共现强度算（需要索引，编译不再纯粹）
- 固定按 source 分档：literal 1.0 / synonym 0.8 / derived 0.5（简单，但一刀切）

**倾向先用固定分档，等有评测数据了再调。** 现在没有评测集，
调也是瞎调。

### Q5. 要不要 `dataflow` 算子

「哪些代码修改了这个字段」「这个参数的值从哪来」——这类查询靠 `calls` 边
答不了，需要 def-use 链。

代价：索引要扩，Java 侧得靠 LSP 或 CodeQL 抽数据流，成本不低。
收益：能回答一整类现在完全答不了的问题。

**先不做，但数据模型里给 `Edge.kind` 留了位置**，将来加不用改算子签名。

### Q6. `co_change` 算子值不值得

「在 git 历史里总是一起改的文件」是很强的信号——
整理这个仓库时，用共现分析找出过真实的抽象泄漏（schema 和它的消费者
每次都一起改）。

但它和代码结构是**正交**的信息源，混进 QL 会让语义变复杂：
`hop(a, b, edge="co_change")` 里的「边」根本不是代码里的边。

**倾向单独做成一个分析工具，不进 QL。**

### Q7. 多语言

现在图库里只有 Java 的调用边（677 条，全部来自 LSP）。
Python / JS / C++ 的解析器有，但没建图。

`hop` 在这些语言上直接不可用。要么补图，要么 `hop` 要能优雅降级
（图缺失时退化成什么？返回空还是跳过约束？）。**降级语义需要定**——
静默跳过约束会让结果不可信。

## 需要先有的东西

### 评测集

[07](07-mapping-to-current.md) 的迁移路径要求「每阶段能回答比老的好在哪」，
但现在**没有评测集**——`evaluation/` 是空骨架，`data/` 里只有几条样例 query。

没有评测，所有关于召回和精度的判断都是猜的。这是**优先级最高的前置工作**，
比实现任何算子都靠前。

至少需要：

- 20–50 条真实查询，覆盖不同类型（词法为主 / 图为主 / 语义为主）
- 每条查询的人工标注答案集
- 一套指标（代码检索一般用 MRR / Recall@k / nDCG@k）

### 一个能跑通的最小 QL

在动编译器之前，先手写 3–5 段 QL 脚本覆盖不同查询类型，
验证**算子集合够不够用**。写不出来的地方就是缺的算子。

这一步很便宜（几百行），但能避免把编译器建在错的算子集上。
