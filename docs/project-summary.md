# CodeSense 项目简介

## 想解决的问题

当前 Coding Agent 的代码搜索主要依赖 `grep`：Agent 根据自然语言任务自行构造正则表达式，再逐步搜索和阅读代码。这种方式简单、通用，但搜索质量高度依赖 Agent 对当前项目的认知。只有当 Agent 已经知道项目采用了哪些命名、模块划分和实现惯例时，才能写出高质量的正则；面对陌生代码库或“限流”“背压”“状态一致性”这类不一定直接出现在标识符中的概念时，很容易搜偏或漏掉关键代码。

CodeSense 希望解决自然语言意图与项目实际代码表达之间的落差：把自然语言问题编译成可执行、可组合的代码查询，而不是只翻译成更多关键词。

## 项目意义

CodeSense 面向 Coding Agent 提供更稳定的语义搜索能力，使 Agent 即使缺少项目先验，也能结合项目词汇、代码结构和语义判断定位相关实现。同时，查询过程和结果保留命中词、结构关系及判断理由等证据，便于检查、修改和复现，减少依赖模型一次性“猜对搜索词”。

## 已完成的工作

项目目前已实现从源码索引到查询执行的基本链路：解析代码声明并构建符号表、分域倒排索引和代码关系图；从项目语料中学习标识符切分与概念接地；将自然语言查询编译为由基本算子组成的 Python QL 脚本；执行脚本并返回带证据的代码片段。项目也在基于真实 Agent 轨迹和 reference patch 构造语义搜索评测，用于衡量系统能否定位开发者实际修改的文件和函数。

## 不重点关注的方向

项目聚焦的是语义搜索，尤其是“用户表达的概念如何对应到特定项目中的命名与实现”以及“如何组合多种证据回答复杂查询”。对于关键词匹配、正则搜索、基础符号跳转和简单代码图谱查询等已经较成熟的能力，CodeSense 不计划投入大量工作重复优化，而会优先复用现有搜索引擎、解析器、语言服务和代码图工具的业界进展，并将它们作为语义查询的底层算子。
