🎯 代码语义相似度模型训练方案

核心思想：Word2Vec 范式的自监督学习

不需要任何人工标注！模型通过符号的上下文共现模式自动学习语义相似性。 就像 Word2Vec 能自动学到 king-man+woman≈queen 一样，我们的模型能自动学到 readahead≈ra。

为什么选择 Word2Vec 范式？

❌ 传统有监督方法

  • 需要人工标注正负样本对
  • "readahead 和 ra 相似吗？" → 人工回答
  • 数据质量依赖标注者
  • 难以覆盖所有关系类型
  • 无法规模化

✅ Word2Vec 自监督范式

  • 零人工标注
  • 从代码结构中自动学习
  • "readahead 和 ra 经常一起出现" → 自动学习
  • 覆盖所有隐式语义关系
  • 可无限扩展

Word2Vec 的启示

Word2Vec 是如何工作的？

训练数据：大量文本句子

"The king sat on the throne"
"The queen ruled the kingdom"  
"The king and queen were married"

学习方式：预测上下文词

  • 输入: "king" → 预测上下文: {the, sat, on, throne}
  • 输入: "queen" → 预测上下文: {the, ruled, kingdom}

自动学到的结果：

  • king 和 queen 有相似的上下文 → 向量相似
  • 无需任何人告诉模型 "king 和 queen 相关"

迁移到代码符号相似性

训练数据：代码文件中的符号共现

// file: mm/readahead.c
void readahead_init() { struct ra *ctx; ra_setup(ctx); }
void ra_submit() { readahead_process(); }

// file: fs/readahead.c  
ssize_t readahead_pages() { ra_count++; }

学习方式：预测上下文符号

  • 输入: "readahead" → 预测上下文: {ra, ra_setup, ra_submit, ...}
  • 输入: "ra" → 预测上下文: {readahead, readahead_init, ...}

自动学到的结果：

  • readahead 和 ra 有相似的上下文 → 向量相似
  • 无需任何人告诉模型 "readahead 缩写为 ra"

关键洞察

🔑 核心洞察：上下文共现 = 隐式语义关系

如果两个符号经常在同一上下文中出现，它们很可能有语义关联：

上下文类型 示例 隐含的语义关系
同文件 readahead.c 中同时有 readahead() 和 ra 可能是缩写/相关概念
同函数 readahead_init() 内调用 ra_setup() 功能相关/调用关系
同类型 struct ra *p; p->readahead_size 类型关联
同调用者 多个函数都调用 readahead 和 ra 功能等价

模型会自动发现这些隐式关系，无需任何标注！

📦 第一部分：数据构建

数据构建总览

核心思路：为每个符号构建"上下文窗口"

类比 Word2Vec 对每个词取前后 N 个词作为上下文，我们对每个符号取多种上下文：

# Word2Vec 的上下文：前后 N 个词 "The cat sat on the mat" ↑ 上下文: {The, sat, on, the, mat} # 我们的方法：代码结构上下文 file: mm/readahead.c ├── function: readahead_init() │ ├── symbols: {readahead_init, ra, ra_setup, ctx} │ └── readahead 的上下文: {ra, ra_setup, ctx, readahead_init} │ ├── function: ra_submit() │ ├── symbols: {ra_submit, readahead_process, ra} │ └── ra 的上下文: {readahead_process, ra_submit}

关键：readahead 和 ra 共享相似上下文 → 模型自动学习相似

上下文定义

符号的"上下文" = 与之共现的其他符号集合

对于每个符号 S，我们定义四种上下文：

符号 S = "readahead" 上下文1: 文件级上下文 (File Context) → 同一文件中出现的所有其他符号 → {ra, ra_setup, ra_submit, ra_count, readahead_init, ...} 上下文2: 函数级上下文 (Function Context) → 同一函数内出现的符号 → readahead_init() 内: {ra, ctx, ra_setup} 上下文3: 调用链上下文 (Call Graph Context) → 调用 S 的函数 (callers) → 被 S 调用的函数 (callees) → callers: {do_readahead, generic_readahead} → callees: {ra_setup, ra_submit} 上下文4: 类型关联上下文 (Type Context) → S 所属的类型/容器 → S 包含的子符号 → container: "struct readahead_state" → contains: {readahead_size, readahead_async}

上下文窗口示例

代码片段：

// file: mm/readahead.c
struct ra_context {              // 类型定义
    int ra_size;                 // 成员变量
    void *ra_buffer;
};

void readahead_init(struct ra_context *ctx) {  // 函数
    ctx->ra_size = 1024;
    ra_setup(ctx->ra_buffer);    // 函数调用
}

void ra_submit(struct ra_request *req) {
    readahead_process(req);
}

符号 "readahead" 的上下文：

{
    "symbol": "readahead",
    "contexts": {
        "file": ["ra_context", "ra_size", "ra_buffer", "readahead_init", 
                 "ctx", "ra_setup", "ra_submit", "ra_request", "readahead_process"],
        "function": ["ctx", "ra_size", "ra_buffer", "ra_setup"],  // 在 readahead_init 内
        "callers": ["do_readahead", "generic_readahead"],  // 调用 readahead_init 的函数
        "callees": ["ra_setup"],
        "type": ["readahead_init"],  // 作为函数名前缀
        "container": []
    }
}

符号 "ra" 的上下文：

{
    "symbol": "ra",
    "contexts": {
        "file": ["readahead", "readahead_init", "readahead_process", "ra_context", ...],
        "function": ["ctx", "ra_size", "ra_setup"],
        "callers": ["readahead_init"],
        "callees": [],
        "type": ["ra_context", "ra_size", "ra_buffer", "ra_submit", "ra_request"],
        "container": []
    }
}

模型自动发现：

readahead 和 ra 有高度重叠的上下文 → 向量相似度高

四种上下文类型详解

上下文类型 定义 获取方式 学习到的关系
文件级
File Context		 同一源文件中的所有符号 从 symbols_index.json 按 file 分组 • 缩写关系
• 同领域概念
• 模块内相关
函数级
Function Context		 同一函数体内出现的符号 AST 解析函数体，提取符号 • 功能相关
• 数据流关联
• 局部变量关系
调用链
Call Graph Context		 调用者和被调用者 从 call_graph.json 提取 • 功能等价
• 接口关系
• 模块边界
类型关联
Type Context		 所属类型/容器，包含的成员 从 symbols_index.json 的 container 字段 • 继承关系
• 组合关系
• 命名约定

上下文权重

不同上下文类型对相似性的贡献不同，可设置权重：

context_score = 0.4 × file_context + 0.3 × function_context + 0.2 × call_context + 0.1 × type_context

数据构建脚本

完整脚本

#!/usr/bin/env python3 """ 符号上下文数据构建脚本 类比 Word2Vec 从文本中提取词的上下文， 本脚本从代码中提取符号的上下文。 输入: symbols_index.json, call_graph.json 输出: symbol_contexts.jsonl """ import json import argparse from pathlib import Path from collections import defaultdict from typing import Dict, List, Set class SymbolContextBuilder: """构建符号上下文数据""" def __init__(self, symbols_path: str, calls_path: str): self.symbols = self._load_json(symbols_path) self.call_graph = self._load_json(calls_path) # 构建索引 self._build_indices() def _load_json(self, path: str) -> list: with open(path, 'r', encoding='utf-8') as f: return json.load(f) def _build_indices(self): """构建各种索引""" # 文件 -> 符号列表 self.file_symbols = defaultdict(list) for s in self.symbols: self.file_symbols[s["file"]].append(s["name"]) # 函数 -> 符号列表 (简化：使用文件内符号近似) # 实际实现可通过 AST 解析函数体 # 调用关系索引 self.callers = defaultdict(set) # callee -> callers self.callees = defaultdict(set) # caller -> callees for edge in self.call_graph: self.callers[edge["callee"]].add(edge["caller"]) self.callees[edge["caller"]].add(edge["callee"]) # 类型/容器索引 self.type_members = defaultdict(set) for s in self.symbols: if s.get("container"): self.type_members[s["container"]].add(s["name"]) def build_contexts(self) -> List[Dict]: """为每个符号构建上下文""" results = [] for sym in self.symbols: name = sym["name"] file = sym["file"] contexts = { "symbol": name, "file": file, "contexts": [] } # 1. 文件级上下文：同文件的其他符号 file_context = [ s for s in self.file_symbols[file] if s != name ] # 2. 调用链上下文 caller_context = list(self.callers.get(name, set())) callee_context = list(self.callees.get(name, set())) # 3. 类型上下文 container = sym.get("container", "") type_context = list(self.type_members.get(container, set())) # 合并所有上下文 all_contexts = set() all_contexts.update(file_context) all_contexts.update(caller_context) all_contexts.update(callee_context) all_contexts.update(type_context) contexts["contexts"] = list(all_contexts) contexts["file_context"] = file_context contexts["callers"] = caller_context contexts["callees"] = callee_context if all_contexts: # 只保留有上下文的符号 results.append(contexts) return results def save(self, output_path: str, results: List[Dict]): """保存结果""" path = Path(output_path) path.parent.mkdir(parents=True, exist_ok=True) with open(path, 'w', encoding='utf-8') as f: for item in results: f.write(json.dumps(item, ensure_ascii=False) + '\n') print(f"Saved {len(results)} symbol contexts to {output_path}") def main(): parser = argparse.ArgumentParser() parser.add_argument("--symbols", required=True, help="symbols_index.json path") parser.add_argument("--calls", required=True, help="call_graph.json path") parser.add_argument("--output", required=True, help="output jsonl path") args = parser.parse_args() builder = SymbolContextBuilder(args.symbols, args.calls) results = builder.build_contexts() builder.save(args.output, results) if __name__ == "__main__": main()

🧠 第二部分：模型训练

模型架构

选择：Word2Vec 风格的 Skip-gram 模型

直接使用 Word2Vec 的训练方法，把符号当作"词"，上下文当作"上下文词"：

Word2Vec Skip-gram 目标： 给定目标词 w，最大化其上下文词 c 的出现概率： L = Σ log P(c | w) P(c | w) = exp(v_c · v_w) / Σ exp(v_i · v_w) 我们的目标（完全相同）： 给定符号 s，最大化其上下文符号 c 的出现概率： L = Σ log P(c | s) P(c | s) = exp(v_c · v_s) / Σ exp(v_i · v_s) → 训练后，readahead 和 ra 的向量会相似，因为它们有相似的上下文！

  • ✅ 模型文件小（几MB）

训练目标

Skip-gram 训练过程

训练样本：

从 symbol_contexts.jsonl 读取：

(symbol="readahead", contexts=["ra", "ra_setup", "ra_submit", ...])
(symbol="ra", contexts=["readahead", "readahead_init", ...])

转换为 Skip-gram 训练对：
("readahead", "ra")      ← 正样本
("readahead", "ra_setup") ← 正样本
("ra", "readahead")       ← 正样本
...

训练过程：

  1. 输入 (target="readahead", context="ra")
  2. 模型尝试让 v_readahead · v_ra 最大
  3. 同时，负采样让 v_readahead · v_random 最小
  4. 训练后，readahead 和 ra 的向量相似度高

负采样 (Negative Sampling)

为了加速训练，使用负采样而非 softmax：

L = log σ(v_c · v_s) + Σ log σ(-v_n · v_s)

其中：

  • v_s: 目标符号向量
  • v_c: 正上下文符号向量
  • v_n: 负采样符号向量（随机选择）

训练脚本

完整训练脚本

#!/usr/bin/env python3 """ 符号相似度模型训练脚本 使用 Word2Vec Skip-gram 方法训练符号向量。 训练后，语义相关的符号会有相似的向量。 用法: python train_symbol_embedding.py \ --input data/project/symbol_contexts.jsonl \ --output models/project/symbol_embedding \ --dim 100 \ --window 10 \ --epochs 10 """ import json import argparse from pathlib import Path from gensim.models import Word2Vec from typing import List def load_training_data(jsonl_path: str) -> List[List[str]]: """ 加载训练数据 将 (symbol, contexts) 转换为 Skip-gram 所需的序列格式： [symbol, context1, context2, ...] 每个符号及其上下文构成一个"句子" """ sequences = [] with open(jsonl_path, 'r', encoding='utf-8') as f: for line in f: data = json.loads(line) symbol = data["symbol"] contexts = data["contexts"] if len(contexts) >= 2: # 至少有2个上下文 # 构成序列：[target, context1, context2, ...] seq = [symbol] + contexts sequences.append(seq) print(f"Loaded {len(sequences)} training sequences") return sequences def train_word2vec( sequences: List[List[str]], vector_size: int = 100, window: int = 10, min_count: int = 2, epochs: int = 10, negative: int = 5, workers: int = 4 ) -> Word2Vec: """ 训练 Word2Vec 模型 参数说明： - vector_size: 向量维度 - window: 上下文窗口大小 - min_count: 忽略出现次数少于此值的符号 - epochs: 训练轮数 - negative: 负采样数量 """ model = Word2Vec( sentences=sequences, vector_size=vector_size, window=window, min_count=min_count, sg=1, # Skip-gram 模式 negative=negative, workers=workers, epochs=epochs ) return model def test_similarity(model: Word2Vec, test_pairs: List[tuple]): """测试相似度""" print("\n=== Similarity Test ===") for w1, w2, expected in test_pairs: if w1 in model.wv and w2 in model.wv: score = model.wv.similarity(w1, w2) status = "✓" if (score > 0.5) == expected else "✗" print(f"{status} {w1:20} vs {w2:20} → {score:.3f}") else: print(f"✗ {w1:20} or {w2:20} not in vocabulary") def main(): parser = argparse.ArgumentParser() parser.add_argument("--input", required=True, help="symbol_contexts.jsonl") parser.add_argument("--output", required=True, help="output model path") parser.add_argument("--dim", type=int, default=100, help="vector dimension") parser.add_argument("--window", type=int, default=10, help="context window") parser.add_argument("--epochs", type=int, default=10, help="training epochs") parser.add_argument("--min_count", type=int, default=2, help="min symbol frequency") args = parser.parse_args() # 1. 加载数据 print("Loading training data...") sequences = load_training_data(args.input) # 2. 训练模型 print(f"Training Word2Vec (dim={args.dim}, epochs={args.epochs})...") model = train_word2vec( sequences, vector_size=args.dim, window=args.window, epochs=args.epochs, min_count=args.min_count ) # 3. 保存模型 output_path = Path(args.output) output_path.parent.mkdir(parents=True, exist_ok=True) model.save(str(output_path)) print(f"Model saved to {args.output}") # 4. 输出统计 print(f"\n=== Model Statistics ===") print(f"Vocabulary size: {len(model.wv)}") print(f"Vector dimension: {model.wv.vector_size}") # 5. 测试（可选） test_pairs = [ ("readahead", "ra", True), ("readahead", "read", True), ("authenticate", "auth", True), ("readahead", "database", False), ] test_similarity(model, test_pairs) if __name__ == "__main__": main()

🔮 第三部分：推理使用

推理流程

使用训练好的模型计算相似度

#!/usr/bin/env python3 """ 符号相似度推理模块 加载训练好的 Word2Vec 模型，计算符号间的相似度。 """ from gensim.models import Word2Vec from typing import List, Tuple, Optional class SymbolSimilarity: """符号相似度计算器""" def __init__(self, model_path: str): """加载模型""" self.model = Word2Vec.load(model_path) self.vocab = set(self.model.wv.index_to_key) def similarity(self, symbol1: str, symbol2: str) -> float: """ 计算两个符号的相似度 Returns: float: 相似度分数 [0, 1] """ s1, s2 = symbol1.lower(), symbol2.lower() if s1 not in self.vocab or s2 not in self.vocab: return 0.0 return float(self.model.wv.similarity(s1, s2)) def most_similar( self, symbol: str, topn: int = 10 ) -> List[Tuple[str, float]]: """ 找出最相似的符号 Returns: List of (symbol, score) tuples """ s = symbol.lower() if s not in self.vocab: return [] return self.model.wv.most_similar(s, topn=topn) def filter_candidates( self, target: str, candidates: List[str], threshold: float = 0.5 ) -> List[Tuple[str, float]]: """ 过滤候选符号，返回相似的 Args: target: 目标符号 candidates: 候选符号列表 threshold: 相似度阈值 Returns: List of (candidate, score) tuples, sorted by score """ results = [] for cand in candidates: score = self.similarity(target, cand) if score >= threshold: results.append((cand, score)) results.sort(key=lambda x: x[1], reverse=True) return results def is_abbreviation( self, full_name: str, abbr: str, threshold: float = 0.6 ) -> bool: """ 判断 abbr 是否是 full_name 的缩写 基于向量相似度，如果二者相似度高于阈值，则认为是缩写关系 """ return self.similarity(full_name, abbr) >= threshold # 使用示例 if __name__ == "__main__": sim = SymbolSimilarity("models/project/symbol_embedding") # 测试相似度 print(sim.similarity("readahead", "ra")) # 0.847 print(sim.similarity("authenticate", "auth")) # 0.783 # 找相似符号 print(sim.most_similar("readahead", topn=5)) # [('ra', 0.847), ('readahead_init', 0.721), ('ra_submit', 0.698), ...] # 过滤候选 candidates = ["ra", "rd", "rea", "rhd", "read", "write", "db"] print(sim.filter_candidates("readahead", candidates, threshold=0.5)) # [('ra', 0.847), ('read', 0.652), ('rea', 0.581)]

常见问题

Q1: 为什么 Word2Vec 能自动学到缩写关系？

答案：因为缩写和全称经常在同一上下文出现！

// 在同一文件中
void readahead() { ... }    // 全称
struct ra *ctx;             // 缩写

// readahead 和 ra 都出现在 mm/readahead.c
// 它们的上下文重叠 → 向量相似 → 模型自动学到关联

这就像 Word2Vec 能学到 king 和 queen 相似，因为它们有相似的上下文一样。

Q2: 需要多少数据才能训练出好效果？

答案：比想象中少得多！

  • 小项目（1000-5000 符号）：效果已经不错
  • 中项目（5000-20000 符号）：效果很好
  • 大项目（20000+ 符号）：效果最佳

关键不是数据量，而是符号间的共现模式是否明显。

Q3: 训练需要多久？

答案：非常快！Word2Vec 训练速度极快。

  • 10000 符号：约 1-2 分钟
  • 50000 符号：约 5-10 分钟
  • 100000 符号：约 15-20 分钟

Q4: 如果符号不在词表中怎么办？

答案：有几种策略：

  • 策略1：返回 0 相似度（保守）
  • 策略2：使用 FastText 支持子词，可处理未登录词
  • 策略3：回退到通用模型（如 sentence-transformers）

  2. Word2Vec 范式：符号当作词，上下文符号当作上下文词
  3. 上下文定义：文件级 + 函数级 + 调用链 + 类型关联
  4. 训练快速：Word2Vec 训练，几分钟内完成
  5. 效果精准：项目特定，比通用模型更懂项目命名约定
