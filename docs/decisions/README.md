# 设计决策记录（ADR）

记录**为什么当初这么设计**，尤其是「为什么不用更简单的做法」。

代码能告诉你现在是怎么做的，但告诉不了你当初否决过什么。半年后有人觉得
某处设计多余想简化掉，翻这里能看到当初是不是已经试过、为什么退回来了。

## 什么时候写一份

- 做了一个**不可逆或改起来很贵**的选择（数据 schema、模块边界、外部依赖）
- 选了一个**看起来更复杂**的方案，需要解释为什么不用简单那个
- 组里为某个做法争论过，最后定下来了

日常改代码不用写。**加一个过滤器不用写，改变过滤器的组合方式要写。**

## 命名

`NNNN-短横线描述.md`，序号只增不减。

已经生效的决策不要原地改。想推翻它就开一份新的，在新的里写明
「取代 0001」，并在旧的顶部标一行「已被 000X 取代」。

## 模板

```markdown
# NNNN. <一句话结论>

- 状态：接受 / 已被 000X 取代
- 日期：YYYY-MM-DD

## 背景
当时面对什么问题？有哪些约束？

## 决策
决定怎么做。

## 被否决的方案
每个方案写清楚：它是什么、为什么当时看着可行、为什么最后没选。
**这一节是整份文档最有价值的部分**，不要省。

## 代价
这个决策带来了什么麻烦？什么情况下应该重新考虑它？
```
